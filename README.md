# RV64IM Single-Cycle Processor (VHDL)

A 64-bit single-cycle RISC-V processor written in VHDL. It implements **RV64I**, the **M** extension, **Zba / Zbb / Zbs** instructions and a set of **custom** instructions placed in the custom-0 (R-type) and custom-1 (I-type) opcode slots. Every instruction executes in one clock cycle. The instruction memory and the data memory are external to the core.

## Datapath architecture

![RV64IM CPU datapath](CPU_Datapath.png)

## Instruction set

114 instructions, all 32 bits wide.

| Group | Count |
|:--|:-:|
| RV64I | 52 |
| M | 13 |
| Zba | 4 |
| Zbb | 18 |
| Zbs | 8 |
| Custom | 19 |
| **Total** | **114** |

- Opcode `0001011` (custom-0) carries 35 R-type encodings: the 12 custom R-type instructions plus the Zba, Zbb and Zbs instructions that are not at their official encodings.
- Opcode `0101011` (custom-1) carries 8 I-type encodings: 7 custom instructions plus `RORI`.
- `ADD.UW`, `RORIW`, `BSETI`, `BCLRI`, `BINVI` and `BEXTI` use their official encodings.
- Standard toolchains do not know the custom-0 and custom-1 encodings, so instructions placed in those slots need a custom assembler.
- `FENCE`, `ECALL` and `EBREAK` are decoded and have no effect (no traps, no CSRs).

The full list with `opcode`, `funct3` and `funct7` fields and the operation of each custom instruction is in [Supported Instructions.md](Supported%20Instructions.md).

## Control

### Main control signals

Generated by `Control` from `opcode` (instruction bits `[6:0]`). Unlisted signals are `0` / `00`.

| Instruction class | `opcode` | RegWrite | MemRead | MemWrite | ALUSrcA | ALUSrcB | RegSrc | PCSrc | ALUOpcode |
|:--|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| OP | `0110011` | `1` | `0` | `0` | `0` | `0` | `00` | `00` | `010` |
| OP-32 | `0111011` | `1` | `0` | `0` | `0` | `0` | `00` | `00` | `100` |
| OP-IMM | `0010011` | `1` | `0` | `0` | `0` | `1` | `00` | `00` | `011` |
| OP-IMM-32 | `0011011` | `1` | `0` | `0` | `0` | `1` | `00` | `00` | `101` |
| LUI | `0110111` | `1` | `0` | `0` | `0` | `0` | `11` | `00` | `000` |
| AUIPC | `0010111` | `1` | `0` | `0` | `1` | `1` | `00` | `00` | `000` |
| Load | `0000011` | `1` | `1` | `0` | `0` | `1` | `01` | `00` | `000` |
| Store | `0100011` | `0` | `0` | `1` | `0` | `1` | `0` | `00` | `000` |
| Branch | `1100011` | `0` | `0` | `0` | `0` | `0` | `0` | `01` | `001` |
| JALR | `1100111` | `1` | `0` | `0` | `0` | `1` | `10` | `11` | `000` |
| JAL | `1101111` | `1` | `0` | `0` | `1` | `1` | `10` | `10` | `000` |
| Custom-0 (R-type) | `0001011` | `1` | `0` | `0` | `0` | `0` | `00` | `00` | `110` |
| Custom-1 (I-type) | `0101011` | `1` | `0` | `0` | `0` | `1` | `00` | `00` | `111` |

Any other `opcode` (including `FENCE` and `SYSTEM`) leaves all control signals at their default value.

| Signal | Value | Meaning |
|:--|:-:|:--|
| `ALUSrcA` | `0` / `1` | ALU operand A = `rs1` / PC |
| `ALUSrcB` | `0` / `1` | ALU operand B = `rs2` / immediate |
| `RegSrc` | `00` | Write-back = ALU result |
| | `01` | Write-back = memory read data |
| | `10` | Write-back = `PC + 4` |
| | `11` | Write-back = immediate (LUI) |
| `PCSrc` | `00` | Next PC = `PC + 4` |
| | `01` | Next PC = `PC + Imm` if the branch condition holds, else `PC + 4` |
| | `10` | Next PC = ALU result (JAL) |
| | `11` | Next PC = ALU result with bit 0 cleared (JALR) |

### ALU control

`ALUControl` maps `ALUOpcode` plus `funct3` / `funct7` to `ALUSelect`.

| `ALUOpcode` | Source | Decoded by |
|:-:|:--|:--|
| `000` | Loads, stores, AUIPC, JAL, JALR | Always ADD |
| `001` | Branches | `funct3`: EQ, NE, LT (BLT, BGE), LTU (BLTU, BGEU) |
| `010` | OP: RV64I and M register-register | `funct3`, `funct7` |
| `011` | OP-IMM: RV64I immediates, Zbs immediates | `funct3`, `funct6` (`funct7[6:1]`) |
| `100` | OP-32: RV64I and M word operations, `ADD.UW` | `funct3`, `funct7` |
| `101` | OP-IMM-32: `ADDIW`, word shift immediates, `RORIW` | `funct3`, `funct7` |
| `110` | Custom-0 R-type | `funct3`, `funct7` |
| `111` | Custom-1 I-type | `funct3` |

### ALU operation select

`ALU` decodes the 6-bit select `S` into a one-hot 64-bit enable vector. Every result is computed in parallel and the selected one is passed to `Result` through an AND-OR multiplexer. `Zero` is asserted when `Result` is all zeros.

| `S` | Group | Operations |
|:-:|:--|:--|
| 0 - 18 | Arithmetic | ADD, SUB, ADDW, SUBW, ABS, ABSW, MUL, MULH, MULHSU, MULHU, MULW, DIV, DIVU, DIVW, DIVUW, REM, REMU, REMW, REMUW |
| 19 - 28 | Logic | NOT, AND, OR, XOR, ANDN, ORN, XORN, NAND, NOR, XNOR |
| 29 - 34 | Compare | EQ, NE, LT, LTU, LE, LEU (result is `0` or `1`) |
| 35 - 44 | Shift / rotate | SLL, SRL, SRA, ROL, ROR, SLLW, SRLW, SRAW, ROLW, RORW |
| 45 - 48 | Min / max | MIN, MINU, MAX, MAXU |
| 49 - 51 | Bit count | CLZ, CTZ, CPOP |
| 52 - 57 | Shift-and-add | SH1ADD, SH2ADD, SH3ADD, SH4ADD, SH8ADD, ADD.UW |
| 58 - 61 | Single-bit | BSET, BCLR, BINV, BEXT |
| 62 - 63 | Byte operations | REV8, ORC.B |

Behaviour notes:

- 64-bit shifts and rotates use `B[5:0]` as the amount; word (`W`) variants use `B[4:0]`.
- `W` operations work on the low 32 bits and sign-extend the 32-bit result to 64 bits.
- Division by zero: `DIV`, `DIVU`, `DIVW`, `DIVUW` return all ones; `REM`, `REMU` return the dividend; `REMW`, `REMUW` return the sign-extended low 32 bits of the dividend.

## Immediate generation

`ImmGen` selects the immediate format from `opcode` (and `funct3` where needed). Unsupported combinations produce `0`.

| Format | Instructions | Immediate |
|:--|:--|:--|
| I | Loads, `JALR`, `ADDI`, `SLTI`, `SLTIU`, `XORI`, `ORI`, `ANDI`, `ADDIW`, custom-1 `NANDI`, `NORI`, `XNORI`, `SLEI`, `SLEUI`, `ANDNI` | `[31:20]`, sign-extended |
| Shift | `SLLI`, `SRLI`, `SRAI`, `BSETI`, `BCLRI`, `BINVI`, `BEXTI` | `[25:20]`, zero-extended |
| Shift-W | `SLLIW`, `SRLIW`, `SRAIW`, `RORIW` | `[24:20]`, zero-extended |
| Custom shift | `ROLI`, `RORI` | `[25:20]`, zero-extended; `0` unless `[31:26] = 000000` |
| S | Stores | `[31:25]` and `[11:7]`, sign-extended |
| U | `LUI`, `AUIPC` | `[31:12] << 12`, sign-extended |
| B | Branches | `[31]`, `[7]`, `[30:25]`, `[11:8]`, `0`, sign-extended |
| J | `JAL` | `[31]`, `[19:12]`, `[20]`, `[30:21]`, `0`, sign-extended |

## Program counter and branching

- `PCRegister` holds the 64-bit PC and updates it on every rising clock edge with the output of `PCControl`.
- `PC + 4` and `PC + Imm` are computed by two dedicated adders. For `JAL` and `JALR` the target is computed by the ALU (`PC + Imm` and `rs1 + Imm`).
- Branches reuse the ALU compare operations and the `Zero` flag. The branch condition is

  `Branch = (NOT Zero) XOR (funct3[2] AND funct3[0])`

  `BEQ` and `BNE` use the EQ / NE result directly. `BLT` and `BGE` use LT, `BLTU` and `BGEU` use LTU; the `funct3[2] AND funct3[0]` term inverts the condition for `BGE` and `BGEU`.
- `JAL` and `JALR` write `PC + 4` to `rd`. `JALR` clears bit 0 of the target address.

## Memory interface

- **Instruction memory:** `InstructionAddress` is the PC and `InstructionIn` is the 32-bit instruction returned for that address. The instruction is consumed combinationally in the same cycle.
- **Data memory:** `MemoryAddress` is the ALU result (`rs1 + imm`) and `MemoryWriteData` is `rs2`. `MemoryWriteEnable` and `MemoryReadEnable` come from the control unit.
- `MemoryMask` carries `funct3` of the load or store: `000` byte, `001` halfword, `010` word, `011` doubleword, `100` unsigned byte, `101` unsigned halfword, `110` unsigned word.
- `MemoryReadData` is written to `rd` unchanged. The data memory therefore performs the byte / halfword / word selection and the sign or zero extension for `LB`, `LH`, `LW`, `LBU`, `LHU`, `LWU`, and stores only the selected low bytes for `SB`, `SH`, `SW`.

## Register file and reset

- 32 registers of 64 bits. `x0` is not stored: it always reads `0` and writes to it are ignored.
- Reads (`rs1` = `[19:15]`, `rs2` = `[24:20]`) are combinational. A write (`rd` = `[11:7]`) happens on the rising clock edge when `RegWrite` is set.
- `Reset` is synchronous: hold it high for at least one rising clock edge. The PC is `0` and all registers are cleared afterwards.
